# 许嵩音乐本地播放器 PRD

## 项目背景

本项目是一个开源音乐播放软件，初期定位为本地运行的 MVP，音乐目录围绕许嵩所有已发行歌曲进行组织。项目本身不提供音乐资源下载、在线播放源、歌词文本或专辑封面，而是提供一个清晰的歌曲目录、专辑浏览体验、临时歌单能力和本地播放能力。

项目初期重点解决以下问题：

- 开发者可以手动维护许嵩歌曲和专辑的结构化元数据。
- 用户可以在本地把自己合法拥有的音频文件映射到对应歌曲。
- 用户可以按专辑浏览歌曲，也可以快速构建临时播放队列。
- 用户可以把整张专辑加入临时播放队列，并调整队列顺序。
- 用户可以为队列里的每首歌设置本次播放次数，默认播放 1 次。
- 项目后期可能上线，因此数据、路径、音频来源和配置不能写死在代码里。

开源仓库只应包含代码、文档、手动维护的事实性元数据、测试数据和自制占位资源，不应包含未经授权的音频、歌词、专辑封面、艺人图片或商业平台抓取内容。

## 目标用户

### 普通听歌用户

- 熟悉许嵩作品，希望按专辑浏览歌曲。
- 本地已有合法音频文件，希望用一个轻量播放器管理播放队列。
- 经常临时组合不同专辑或歌曲进行播放，而不是维护长期固定歌单。
- 希望某些歌曲在本次播放中重复播放多次。

### 项目开发者和维护者

- 负责维护专辑、歌曲、曲序、发行时间等结构化元数据。
- 需要一个可读、可审查、可版本管理的数据目录。
- 需要在不提交受版权保护资源的前提下开发和测试播放器功能。

### 后期部署维护者

- 可能把应用部署为 Web 站点。
- 需要保留接入授权音源、远程配置、云端元数据、账号系统的扩展空间。
- 需要明确开源项目和第三方音乐版权之间的边界。

## 核心使用场景

### 场景 1：按专辑浏览歌曲

用户打开应用后，看到按专辑分组的许嵩歌曲目录。用户进入某张专辑，可以看到该专辑下的歌曲列表、曲序、发行信息和本地音频绑定状态。如果某首歌未绑定本地音频，应用应明确显示“未绑定本地音频”，而不是尝试从网络加载资源。

### 场景 2：把整张专辑加入临时播放队列

用户在专辑页点击或拖动“加入队列”操作，系统把该专辑下的歌曲按专辑曲序追加到临时播放队列。每首歌生成独立的队列项，默认播放次数为 1 次。

### 场景 3：临时组合多张专辑和单曲

用户可以先加入一整张专辑，再从另一张专辑中追加几首单曲。临时队列不要求保存为正式歌单，刷新或重新打开应用后可根据本地持久化策略恢复上次队列。

### 场景 4：调整播放顺序

用户在临时队列中拖拽歌曲，调整播放顺序。拖拽完成后，队列中的显示顺序和实际播放顺序保持一致。

### 场景 5：设置本次播放次数

用户在临时队列中把某首歌的播放次数从 1 调整为 2 或更多。该设置只影响当前队列项，不修改歌曲元数据，也不影响同一首歌在队列中的其他实例。

### 场景 6：本地音频文件映射

用户选择本地音频文件或本地音乐目录，把文件绑定到对应歌曲。绑定信息保存在本地存储中。应用不上传、不复制、不分发该音频文件。

## MVP 功能

### 专辑与歌曲目录

- 展示专辑列表。
- 展示每张专辑下的歌曲列表。
- 支持按专辑曲序排序。
- 展示歌曲标题、所属专辑、曲序、可选发行日期、可选版本说明。
- 展示歌曲是否已绑定本地音频。
- 元数据由开发者手动维护，存放为结构化数据文件。

### 本地音频绑定

- 用户可以为单首歌曲选择本地音频文件。
- 用户可以取消某首歌曲的本地音频绑定。
- 应用保存歌曲 ID 与本地文件引用之间的映射。
- 当文件不可访问时，应用应显示失效状态，并允许用户重新绑定。
- 不在仓库中提交任何真实音频文件。

### 临时播放队列

- 支持把单首歌加入队列。
- 支持把整张专辑按曲序加入队列。
- 支持从队列中移除单个队列项。
- 支持清空整个队列。
- 支持拖拽调整队列项顺序。
- 支持同一首歌在队列中出现多次。
- 每个队列项有独立播放次数，默认值为 1。

### 播放控制

- 支持播放、暂停。
- 支持上一首、下一首。
- 支持显示当前播放歌曲。
- 支持显示播放进度。
- 支持手动拖动进度。
- 支持音量控制。
- 当前队列项播放次数完成后，自动进入下一个队列项。
- 如果当前歌曲未绑定本地音频，播放时应提示用户先绑定文件。

### 本地持久化

- 保存本地音频绑定关系。
- 保存当前临时队列。
- 保存队列项播放次数。
- 保存基础播放器设置，例如音量。
- 本地数据结构应使用稳定 ID，不依赖硬编码数组下标。

### 开源与版权边界

- 仓库包含版权说明文档。
- 仓库 `.gitignore` 应排除常见音频、歌词和封面文件格式。
- 示例资源只能使用自制占位图、空白资源或明确可开源分发的测试资源。
- 文档明确说明项目不提供、不托管、不分发任何未经授权的音乐、歌词或封面。

## 非目标功能

当前阶段不做以下功能：

- 不做在线音乐播放源。
- 不做音乐下载。
- 不做歌词展示、逐字歌词、歌词翻译。
- 不做真实专辑封面、艺人照片、MV 截图展示。
- 不做账号系统、登录注册、会员系统。
- 不做云端歌单同步。
- 不做评论、弹幕、点赞、收藏、排行榜。
- 不做推荐算法。
- 不做从音乐平台抓取歌曲、歌词、封面或评论。
- 不做移动端 App。
- 不做桌面安装包，除非 Web MVP 的本地文件体验不足再评估。
- 不做商业化功能。
- 不承诺第一版补齐所有已发行歌曲元数据，第一版可先维护一部分样例数据和元数据规范。

## 用户操作流程

### 首次打开应用

1. 用户打开本地开发环境中的应用。
2. 应用加载内置的专辑和歌曲元数据。
3. 应用展示专辑列表和歌曲绑定状态。
4. 对于未绑定音频的歌曲，应用显示未绑定状态。

### 绑定本地音频

1. 用户进入专辑详情页。
2. 用户选择某首歌曲的“绑定本地音频”操作。
3. 用户从本机选择合法拥有的音频文件。
4. 应用记录该歌曲 ID 与本地文件引用的映射。
5. 歌曲状态变为“已绑定”。

### 添加单曲到临时队列

1. 用户在歌曲列表中选择“加入队列”。
2. 应用在队列末尾创建一个新的队列项。
3. 队列项引用该歌曲 ID。
4. 队列项默认播放次数为 1。

### 添加整张专辑到临时队列

1. 用户在专辑列表或专辑详情页选择“整张专辑加入队列”。
2. 应用读取该专辑下的歌曲 ID 列表。
3. 应用按专辑曲序生成多个队列项。
4. 队列项追加到当前临时队列末尾。
5. 每个队列项默认播放次数为 1。

### 调整临时队列

1. 用户在临时队列区域拖拽某个队列项。
2. 应用实时显示拖拽位置。
3. 用户释放后，应用更新队列顺序。
4. 播放器使用更新后的顺序继续播放。

### 设置播放次数

1. 用户在临时队列中找到某个队列项。
2. 用户通过数字输入、加减按钮或步进控件修改播放次数。
3. 应用校验播放次数必须为正整数。
4. 应用把该值保存到当前队列项。
5. 播放到该队列项时，播放器按设置次数重复播放后再进入下一项。

### 播放队列

1. 用户点击播放按钮。
2. 应用检查当前队列项是否已绑定可访问的本地音频。
3. 若已绑定，开始播放。
4. 若未绑定或文件不可访问，提示用户重新绑定或跳过。
5. 当前队列项完成指定播放次数后，自动播放下一个队列项。
6. 队列播放完成后，播放器停止并保留队列。

## 核心页面

### 应用主页面

- 左侧或主区域展示专辑列表。
- 右侧或底部展示当前临时播放队列。
- 底部展示播放控制条。
- 页面不依赖固定本地路径或固定音频 URL。

### 专辑列表页

- 展示专辑名称、发行日期、专辑类型、歌曲数量。
- 提供进入专辑详情的入口。
- 提供整张专辑加入队列的操作。
- 不展示真实专辑封面，除非使用自制占位图或用户本地自选图片。

### 专辑详情页

- 展示专辑基础信息。
- 按曲序展示歌曲列表。
- 每首歌展示本地音频绑定状态。
- 每首歌提供绑定音频、取消绑定、加入队列操作。
- 提供整张专辑加入队列操作。

### 临时播放队列面板

- 展示队列项顺序。
- 展示歌曲标题、所属专辑、播放次数、绑定状态。
- 支持拖拽排序。
- 支持修改播放次数。
- 支持移除队列项。
- 支持清空队列。

### 播放控制条

- 展示当前播放歌曲。
- 展示播放/暂停、上一首、下一首。
- 展示播放进度和总时长。
- 支持拖动进度。
- 支持音量设置。
- 显示未绑定音频或文件不可访问的错误状态。

### 设置或数据管理页面

MVP 可以做成简单页面或弹窗：

- 查看本地音频绑定数量。
- 清除所有本地音频绑定。
- 清空本地临时队列。
- 查看项目版权声明入口。
- 后期可扩展为远程数据源配置、授权音源配置、账号设置。

## 核心数据对象

### Album

表示一张专辑或正式发行集合。

字段建议：

- `id`：稳定唯一 ID，例如 `vae_2009_custom`。
- `title`：专辑名。
- `artist`：艺人名，MVP 中为 `许嵩`。
- `releaseDate`：发行日期，可为空。
- `type`：类型，例如 `album`、`ep`、`single_collection`。
- `sortOrder`：展示排序。
- `trackIds`：该专辑包含的歌曲 ID 列表。
- `description`：开发者维护的简短说明，不复制商业平台文案。

### Track

表示一首歌曲的事实性元数据。

字段建议：

- `id`：稳定唯一 ID。
- `title`：歌曲名。
- `artist`：艺人名，MVP 中为 `许嵩`。
- `albumId`：所属专辑 ID。
- `discNumber`：碟号，默认 1。
- `trackNumber`：专辑内曲序。
- `durationSeconds`：时长，可为空，由开发者维护或后期从本地文件读取。
- `releaseDate`：发行日期，可为空。
- `version`：版本说明，例如 `正式版`、`Live`、`重制版`，可为空。
- `credits`：可选创作信息，只维护事实性字段，避免复制平台长文案。

### LocalAudioAsset

表示用户本地音频文件与歌曲之间的绑定关系。

字段建议：

- `id`：本地绑定记录 ID。
- `trackId`：对应歌曲 ID。
- `fileName`：用户选择的文件名。
- `fileType`：文件 MIME 类型。
- `fileSize`：文件大小。
- `fileHandle`：浏览器或桌面环境可用的本地文件引用。
- `lastVerifiedAt`：上次确认文件可访问的时间。
- `status`：`available`、`missing`、`permission_required`。

注意：该对象只保存本地引用和必要元信息，不把音频文件复制进仓库，也不上传到服务端。

### QueueSession

表示当前临时播放队列。

字段建议：

- `id`：队列会话 ID。
- `name`：队列名称，MVP 可固定为 `临时队列`。
- `items`：队列项列表。
- `createdAt`：创建时间。
- `updatedAt`：更新时间。

### QueueItem

表示临时队列中的一个播放项。

字段建议：

- `id`：队列项 ID。
- `trackId`：引用的歌曲 ID。
- `order`：当前队列顺序。
- `playCount`：本次队列中需要播放的次数，默认 1。
- `playedCount`：当前队列项已经完成的播放次数。
- `source`：加入来源，例如 `single` 或 `album`。
- `sourceAlbumId`：如果来自整张专辑加入，则记录来源专辑 ID。

同一首歌可以对应多个 `QueueItem`。播放次数属于 `QueueItem`，不属于 `Track`。

### PlaybackState

表示播放器运行状态。

字段建议：

- `currentQueueItemId`：当前播放的队列项 ID。
- `isPlaying`：是否正在播放。
- `positionSeconds`：当前播放进度。
- `volume`：音量。
- `repeatMode`：MVP 可先只支持 `none`。
- `error`：当前播放错误，例如未绑定音频或文件不可访问。

### UserSettings

表示用户本地设置。

字段建议：

- `volume`：默认音量。
- `lastOpenedAlbumId`：上次查看的专辑 ID。
- `theme`：主题设置，MVP 可选。
- `metadataSource`：元数据来源，MVP 为本地内置数据，后期可扩展为远程 URL。

## 验收标准

### 专辑与歌曲目录

- 应用启动后能加载至少一组开发者维护的专辑和歌曲元数据。
- 专辑页能按曲序展示歌曲。
- 歌曲 ID、专辑 ID 在刷新后保持稳定。
- 未绑定音频的歌曲不会触发任何网络播放请求。

### 本地音频绑定

- 用户可以为歌曲选择本地音频文件。
- 绑定后，歌曲列表和队列中能显示已绑定状态。
- 取消绑定后，播放该歌曲时应提示重新绑定。
- 刷新页面后，本地绑定关系仍可恢复或提示重新授权。

### 临时队列

- 单曲可以加入队列。
- 整张专辑可以按曲序加入队列。
- 队列允许重复加入同一首歌。
- 队列项可以删除。
- 队列可以清空。
- 拖拽排序后，界面顺序和播放顺序一致。

### 播放次数

- 新增队列项的播放次数默认为 1。
- 播放次数只能设置为正整数。
- 设置为 2 的队列项应连续完整播放 2 次后再进入下一个队列项。
- 同一首歌的不同队列项可以拥有不同播放次数。

### 播放器

- 已绑定本地音频的歌曲可以播放和暂停。
- 播放完成后能自动进入下一个队列项。
- 队列播放结束后播放器停止，并保留队列内容。
- 未绑定或不可访问的音频不会导致应用崩溃。

### 本地持久化

- 刷新页面后，临时队列和播放次数仍然存在。
- 刷新页面后，音量设置仍然存在。
- 本地数据不依赖开发机绝对路径写死在代码中。

### 版权与开源

- 仓库中没有真实音频文件。
- 仓库中没有歌词文件。
- 仓库中没有真实专辑封面或艺人照片。
- 文档明确说明项目非官方，且不提供未经授权的音乐、歌词或封面资源。
- 示例数据不包含从商业音乐平台复制的大段介绍、评论、歌词或封面链接。

## 后期可能扩展的方向

### 数据源扩展

- 把本地静态元数据替换或扩展为远程元数据接口。
- 支持多数据源配置，例如本地 JSON、远程 API、用户自定义目录。
- 引入元数据版本号和迁移机制。

### 授权音源接入

- 在取得合法授权后，接入在线音频播放。
- 支持不同音源供应商的适配层。
- 区分本地文件、授权在线播放、用户自定义音源。

### 桌面端

- 使用 Tauri 提供更稳定的本地文件访问体验。
- 支持扫描本地音乐目录。
- 支持更可靠的文件路径权限管理。

### 正式歌单

- 在临时队列之外增加可命名、可保存的正式歌单。
- 支持从临时队列保存为正式歌单。
- 支持导入、导出歌单配置。

### 账号与同步

- 后期上线后可增加账号系统。
- 同步用户歌单、播放偏好、音频绑定元数据。
- 音频文件本身不应默认同步，除非具备明确授权和存储方案。

### 歌词与封面

- 仅在获得授权或用户本地自行提供的情况下支持歌词和封面。
- 歌词和封面应作为可选本地资源或授权服务返回数据。
- 不把歌词和封面作为开源仓库内容。

### 更完整的播放体验

- 支持随机播放、单曲循环、队列循环。
- 支持快捷键。
- 支持迷你播放器。
- 支持播放历史。
- 支持按专辑、发行年份、歌曲版本筛选。

### 部署与合规

- 提供线上部署配置。
- 增加隐私政策和版权声明页面。
- 对远程接口、第三方资源、用户上传内容增加合规检查。
- 保持前端配置化，避免把 API 地址、音源路径、资源路径写死在代码中。

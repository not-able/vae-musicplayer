# 已保存歌单库、独立播放快照与快速播放

> 本文是下一阶段歌单功能的实现约束。它覆盖右侧窄收藏方块栏、已保存歌单、当前编辑歌单与播放状态分离，以及歌曲行快速播放。每次会话只实施本文的一个阶段；未经明确确认不得把多个阶段合并为一次大改。

## 1. 目标与非目标

目标：

- 在现有临时歌单区域内提供已保存歌单快捷入口，而不新增挤压专辑目录的第三个大栏。
- 允许用户切换、查看和编辑任意歌单，同时让已启动的播放内容保持稳定。
- 提供专辑歌曲和歌单歌曲的可见快速播放按钮。
- 所有歌单数据仅保存在当前浏览器本地；不复制、不上传或分发音频文件。

本阶段不做：

- 账号、云同步、分享、多人协作、联网歌单或推荐。
- 歌单封面、真实艺人图片、歌词或任何受版权保护素材。
- 隐式双击播放。双击可在后续作为桌面快捷方式评估，但始终不能替代可见播放按钮，也不能与歌曲拖拽区域冲突。
- 自动把编辑结果同步到正在播放内容。

## 2. 必须保持的状态边界

以下三个状态必须彼此独立：

```text
歌单库（临时草稿 + 已保存歌单）
        │ 用户查看、编辑、保存
        ▼
当前编辑选择（temporary 或 savedPlaylistId）

播放快照（启动播放时复制出的 occurrence 序列）
        │ 仅播放器读取
        ▼
播放器当前项、进度、暂停/播放状态
```

- 点击收藏方块只改变“当前编辑选择”，不得调用播放器 reducer、重置进度或切换当前歌曲。
- 所有加入、移除、排序和播放次数修改只作用于当前编辑的歌单文档。
- 只有明确的“播放此歌单”“从此歌曲开始播放”“播放单曲”或“应用修改到播放队列”动作可以创建或替换播放快照。
- 播放器不得从正在显示的歌单实时读取顺序。正在播放歌单 A 时，用户可打开并编辑 B；A 的歌曲、occurrence 顺序、播放次数、进度均保持不变。
- 活动播放快照是运行时状态，不随刷新恢复为播放中，也不保存 `isPlaying`、播放进度、媒体 token、`blob:` URL 或文件对象。

## 3. 收藏方块栏的交互与布局

### 桌面端

- 收藏方块栏位于现有临时歌单面板内部右侧，建议宽度约 `56px` 到 `68px`；歌单列表仍占该面板的主要宽度。
- 最上方固定为 `＋` 方块，辅助标签为“新建已保存歌单”。它从当前编辑歌单创建副本，不覆盖来源歌单。
- 其余方块对应已保存歌单，显示首字、短名称或稳定色块，并使用无障碍名称“打开已保存歌单：{name}”。
- 方块的选中态表示当前编辑歌单；独立的播放中标记表示活动播放快照来源。两种状态可以同时出现在不同方块上。
- 方块的重命名、删除和“覆盖保存”必须收纳进更多操作菜单，避免方块栏本身出现多个按钮。

### 窄屏

- 在 `860px` 以下，方块栏移到歌单标题下方，改为横向可滚动的一行；不压缩队列项、播放次数或行内播放按钮。
- 保持 `＋` 方块在可见起点，支持键盘聚焦与横向滚动。

### 保存与切换

- 点击已保存方块：切换当前编辑歌单，不影响活动播放快照。
- 点击 `＋`：打开可关闭的命名弹窗；确认后创建新的已保存歌单。首版必须创建副本，不允许静默覆盖。
- 编辑已保存歌单时，保存到该歌单文档；编辑临时草稿时，保存到临时草稿文档。UI 文案应从“加入临时歌单”调整为“加入当前歌单”。
- 删除已保存歌单只删除其歌单记录，不删除目录元数据、本地音频绑定或已经启动的播放快照。

实施前唯一需要产品确认的选择：首次保存是否要求用户输入名称，还是允许生成“未命名歌单 + 日期”。在确认前，代码不得自行选定名称策略。

## 4. 快速播放规则

### 专辑歌曲行

- 每首专辑歌曲保留一个始终可见的小型播放按钮，不能放入三个点菜单。
- 点击后创建单曲播放快照：只含该 `trackId` 的一个 occurrence，`repeatTotal = 1`。
- 不改动当前编辑歌单或任何已保存歌单。单曲结束后播放器停止，不自动恢复之前的播放快照。

### 歌单歌曲行

- 每个歌单队列项同样提供可见播放按钮。
- 点击后从该队列项的第一次 occurrence 开始播放，即使该项当前配置为重复多次，也必须从 `repeatIndex = 1` 开始。
- 应从该歌单在点击时的完整内容创建播放快照，并将当前索引定位到所选队列项的第一次 occurrence；随后按该歌单的后续 occurrence 顺序播放。
- 如果当前编辑歌单不是活动播放来源，点击该按钮是一次明确的播放来源切换，不需要额外确认。
- 任何双击快捷方式都只能绑定在歌曲标题的非拖拽区域，并保留同等可达的按钮、键盘和屏幕阅读器入口；首版不实现。

## 5. 目标领域模型与持久化边界

可复用现有 `TemporaryPlaylist` / `QueueItem` 的结构规则，但需要从“唯一临时队列”提升为歌单库。建议目标模型：

```ts
interface PlaylistLibrary {
  temporaryPlaylist: PlaylistDocument;
  savedPlaylistIds: readonly EntityId[];
  savedPlaylistsById: Readonly<Record<EntityId, PlaylistDocument>>;
}

interface PlaylistDocument {
  id: EntityId;
  name: string;
  itemIds: readonly EntityId[];
  itemsById: Readonly<Record<EntityId, QueueItem>>;
  createdAt: string;
  updatedAt: string;
}

type PlaylistSelection =
  { kind: "temporary" } | { kind: "saved"; playlistId: EntityId };

type PlaybackSource =
  | { kind: "temporary-playlist" }
  | { kind: "saved-playlist"; playlistId: EntityId }
  | { kind: "album-track-preview"; trackId: EntityId };
```

约束：

- 队列项 ID 只需在所属歌单文档内稳定；创建播放快照时必须生成或携带足以区分来源文档与 occurrence 的运行时身份，不能把不同歌单的同名项误认为同一项。
- 保存的 JSON 只包含稳定 ID、名称、队列项顺序、播放次数和时间戳；不得包含 `File`、`FileSystemFileHandle`、绝对路径、文件名、音频 URL、播放进度、`playedCount`、媒体事件 token 或 React 状态。
- 本地音频绑定继续由现有 IndexedDB 仓储管理，并只在播放器解析播放快照当前 `trackId` 时查询。
- 新歌单库应使用独立、版本化的 localStorage key，例如 `vae-music:playlist-library:v1`；不要把它和目录、播放器设置或音频绑定混存。
- 现有 `vae-music:temporary-playlist:v1` 只能作为迁移来源。新仓储不存在时可读取旧临时歌单生成仅含草稿的库；损坏、未知版本或存储失败必须保留原始数据并报告错误，不能静默清空或覆盖。

## 6. 应用层和播放器改造要求

当前 `src/app/appReducer.ts` 会在每个 `playlist` action 后调用 `syncPlayerSequence`。这正是本功能必须替换的耦合点：后续实现不得继续让“编辑歌单”隐式修改播放器序列。

目标行为：

1. `AppState` 保存歌单库、当前编辑选择和 `PlayerState`。
2. 歌单库 reducer 只修改目标歌单文档，不调用 `syncPlayerSequence`。
3. 明确的启动播放 action 调用纯函数 `createPlaybackSnapshot(document, startQueueItemId?)`，再将序列交给播放器。
4. 单曲播放调用 `createSingleTrackSnapshot(trackId)`；其唯一 occurrence 的总次数固定为 1。
5. `PlayerState` 或紧邻应用状态的运行时对象记录 `PlaybackSource`，用于播放器栏和收藏方块播放中标记；此标记不是“当前编辑选择”。
6. “应用修改到播放队列”不应在首个保存歌单 UI 任务中暗中实现。若后续引入，必须是显式按钮，并定义在当前曲结束后还是立即生效。

目录删除是必须同步处理的例外：

- 删除歌曲或专辑时，从临时草稿、全部已保存歌单和活动播放快照移除涉及的 `trackId`。
- 若被删歌曲正在播放，先停止并释放音频，再把播放器置于安全暂停或空状态。
- 若只删除已保存歌单文档，活动播放快照继续存在，直到自然结束、用户切换播放或刷新页面。

## 7. 实施顺序：一次只做一项

### PLAYLIST-01：歌单库纯规则与版本化仓储

范围：类型、创建/复制/重命名/删除/选择的纯函数、版本化序列化、旧临时歌单迁移、仓储测试。不得修改播放器或 UI。

验收：重复歌曲和独立播放次数在不同保存歌单中互不影响；损坏数据不覆盖旧存储；持久化内容不含音频或运行时字段。

### PLAYLIST-02：播放快照与编辑状态解耦

范围：`appReducer`、播放器序列创建、目录删除联动与纯函数/集成测试。不得实现收藏方块 UI。

验收：播放 A 时编辑 B 不改变 `PlayerState.playSequence`；编辑 A 也不改变已启动快照；显式播放 B 才切换播放；刷新后不自动播放。

### PLAYLIST-03：窄收藏方块栏和保存歌单 UI

范围：歌单面板、命名弹窗、方块菜单、响应式样式和组件测试。不得改变 PLAYLIST-02 的快照规则。

验收：方块切换只改变编辑内容；选中态与播放中标记可区分；桌面不挤压专辑目录，390px 下方块栏横向可滚动；键盘可打开、关闭、选择和删除。

### PLAYER-03：歌曲行快速播放

范围：专辑/歌单歌曲行的可见播放按钮、显式快照启动 action 与测试。双击不在本任务内。

验收：专辑歌曲只播放一次且不改变任何歌单；歌单歌曲从选中项第一次 occurrence 开始；未绑定音频遵循现有错误提示；编辑其他歌单不影响已启动播放。

## 8. 必测场景

- 保存空歌单、含重复歌曲的歌单和含不同播放次数的歌单；刷新后恢复。
- 播放已保存歌单 A 时，切换到 B、调整 B、保存 B；A 的当前项、索引、顺序和次数不变。
- 从 B 的某个队列项快速播放时，序列从该项第一次 occurrence 开始，而不是从当前播放索引或第二次重复开始。
- 从专辑歌曲快速播放时，播放序列长度为 1，且任何歌单文档不变。
- 活动播放来源和当前编辑歌单不同，UI 仍能同时正确标记。
- 删除目录歌曲时，草稿、已保存歌单和活动快照不留下孤儿 `trackId`；删除当前播放歌曲会安全停止。
- 命名弹窗、方块菜单和播放按钮具备中文标签、可见焦点、Esc 关闭和焦点回归。
- 任意持久化字符串均不含音频二进制、绝对路径、`blob:` URL、Cookie、歌词、封面或远程音源。

## 1. 今天完成了什么

今天完成并提交了 `SOURCE-02`：可选的自托管 QQ Music API 元数据导入。

- 提交：`1c8f7fe feat(catalog): add optional QQ metadata import`。
- 目录“导入工具”新增“导入远程元数据”弹窗。用户必须显式填写服务地址，可先测试连接，再手动搜索、查看专辑曲目与本地差异，最后确认导入。
- 新增 `qqMusicCatalogProvider`，仅允许连接检测、搜索、歌手专辑、专辑详情和歌曲详情的最小元数据请求。它不会调用 Cookie、歌词、封面、评论、下载或播放链接接口。

- 已实现超时（10 秒）、HTTP、网络、跨域和响应结构错误的明确提示。Provider 失败不会影响既有本地目录、歌单或本地播放。
- 确认导入时会在同一次用户目录保存中写入：最小的歌手/专辑/歌曲事实字段，以及本地稳定 ID 到外部实体 ID 的映射。不会保存原始响应、Cookie、音频 URL、封面、歌词或评论；删除相应目录项时会同步清理映射。
- 补充 `.env.example`、`README.md`、`docs/metadata.md` 与 2026-07-18 交接记录，明确授权和数据边界。

此前已完成、仍是当前基线的重要能力：本地音频绑定与播放、播放进度/音量、临时与已保存歌单、编辑歌单和播放快照分离，以及专辑/歌单歌曲的显式快速播放。

## 9. 不可遗漏的重要决策

- 元数据 Provider 与播放 Provider 必须独立。QQ Provider 只能提供人工确认的元数据候选，绝不提供音频播放。
- 用户本地文件、队列项和歌曲元数据不保存远程 URL；队列仍只引用 `trackId`。
- 当前编辑歌单与活动播放快照已分离：切换/编辑其他歌单不能隐式改变已开始播放的 occurrence 序列。
- 专辑歌曲快速播放只播放该曲一次且不改变歌单；歌单歌曲快速播放从该队列项的第一次 occurrence 开始。
- 仓库不得提交未经授权的音频、歌词、封面、艺人图、抓取结果、Cookie、账号信息或播放链接。测试资源只能用自制或 `.example.test` 假数据。
- 不要删除、读取或提交 `docs/improve.md`，除非用户明确要求。

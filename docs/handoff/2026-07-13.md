## 7. 已知 bug 或风险

### 功能风险

- 临时歌单仅存在 React 内存状态中，刷新页面会清空。
- “未绑定音频”目前是静态展示，还没有真实映射状态。

## 9. 当前上下文中的重要决策

- 技术栈继续使用 Vite + React + TypeScript + Vitest。
- 项目定位仍是本地优先的音乐播放编排器，不是音乐内容提供方。
- 不引入未经授权的音频、歌词、封面、图片或平台抓取数据。
- 不编造完整真实曲库；当前数据明确标记为占位。
- 专辑和歌曲使用稳定 ID，不依赖数组下标。
- 专辑内曲目顺序以 `album.trackIds` 为权威顺序。
- 同一首歌可以多次进入临时歌单，每次必须拥有独立队列项 ID。
- 播放次数属于队列项，字段名为 `repeatCount`，不属于歌曲元数据。
- 新队列项 `repeatCount` 默认 `1`，`playedCount` 默认 `0`。
- 临时歌单操作优先实现为纯函数，React 组件只负责派发 action 和渲染。
- 当前使用 reducer 管理内存状态，没有引入 Zustand。
- 当前没有持久化，因此没有引入 Dexie。
- 专辑拖入歌单使用原生 HTML Drag and Drop，没有引入 dnd-kit。
- 不使用拖拽作为唯一入口，必须保留按钮备用操作。
- 队列项顺序当前使用上移/下移按钮，队列项拖拽排序尚未实现。
- 右侧临时歌单高度受限，歌曲区域内部滚动。
- 右侧队列项只显示歌曲名和播放次数；专辑名和序号不显示。
- 新增队列项后自动滚动到底部。
- 保持现有 `features/playlist`、`types`、`utils` 目录，不在本任务中大规模重构为 `features/queue`、`domain`。
- 每次只实现一个明确闭环，不同时引入多个 MVP 功能。

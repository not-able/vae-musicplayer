## 已确认的导入规则

- 用户选择单张专辑目录或音乐库根目录均可；每个文件的直接父目录是候选专辑名，不要求固定“音乐库”目录。
- 文件可为 `歌曲名.mp3` 或 `歌手名-歌曲名.flac`；歌手可省略。预览页提供可编辑的本次默认歌手，当前可预填“许嵩”，但扫描与匹配纯函数不得硬编码它。
- `.ext` 是任意扩展名占位，而非实际格式限制；扫描候选支持 `.mp3`、`.flac`、`.m4a`、`.aac`、`.ogg`、`.opus`、`.wav`。能否播放取决于浏览器的实际编码支持。
- 以规范化歌名精确匹配为主。只有唯一内部 `trackId` 才可建议绑定；重名、版本差异、歌手不一致、未知前缀和已有绑定都必须人工确认。
- 文件顺序不决定播放顺序。临时歌单控制播放；目录曲序只是可选展示信息。
- 扫描不写入。预览页可以把未匹配目录生成“专辑名 + 歌曲名 + 默认/解析歌手”的本地草稿，但用户必须显式确认才创建专辑、歌曲与绑定。

## QQ 元数据边界

- 固定流程：用户配置服务地址 → 手动测试或查询 → 预览差异 → 确认导入 → 本地默认展示。不得启动时实时请求或硬编码 `localhost:3200`。
- 本地 `/explorer/metadata` 可访问，但 2026-07-18 搜索“许嵩”时上游在服务端 10 秒超时；Provider 必须处理超时和不可用，且不能阻断本地目录。
- 只保存必要事实字段和可选外部引用；内部稳定 ID 不使用外部 MID。绝不保存或播放音源 URL，也不保存 Cookie、歌词、封面、评论或原始响应。

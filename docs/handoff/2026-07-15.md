### 1.1 修复播放器当前 occurrence 消失后的队列同步

提交：`48b80fc fix: 修复当前播放项消失后的队列同步`

完成的规则：

- 当前播放 occurrence 在新序列中仍存在时，继续保持该 occurrence，不因普通排序或队列更新跳歌。
- 当前 occurrence 因减少 `repeatCount`、删除队列项等操作消失时，从旧播放序列的当前位置之后开始，寻找第一个在新序列中仍存活的 occurrence。
- 找到后切换到该 occurrence；找不到后续存活项时进入 `ended`。
- 删除最后一个正在播放的 occurrence 后，不会回退并重播前面的歌曲。
- 回归测试覆盖了：
  - 缩减重复次数；
  - 删除当前中间项；
  - 删除当前最后项；
  - 通过真实 `move-item` action 排序；
  - 播放中排序以及后续自动推进。

这一改动可通俗理解为“播放队列变动后的续播定位修复”：播放器会沿着用户原本正在听的方向继续，而不是按已经失效的旧数组下标跳歌或倒回重播。

## 7. 已知 bug 或风险

### 7.1 浏览器存储与文件权限

- localStorage 只能可靠保存字符串，不适合保存 `File`，也不能让刷新后的 blob URL 继续有效，因此本次没有用 localStorage 保存音频本体。
- 当前 IndexedDB 方案保存用户所选 `File` 的浏览器本地副本，不等同于长期持有原文件访问权限。原文件被修改后，应用不会自动获得新内容，需要重新绑定。
- IndexedDB 数据受站点来源隔离；协议、域名或端口变化后，原绑定在新来源下不可见。
- IndexedDB 是 best-effort 存储，可能受浏览器配额、隐私模式、用户清理站点数据或存储回收影响。代码已处理存储失败提示，但不能保证数据永不丢失。
- 大音频文件直接保存到 IndexedDB 会占用较多浏览器存储空间。当前 MVP 没有总容量统计或配额预警。
- File System Access API 可以保存文件句柄并更接近原文件，但跨浏览器支持有限、通常要求安全上下文，而且重新打开页面后权限仍可能回到 `prompt`；因此未作为当前默认实现。

### 7.2 真实播放与浏览器差异

- 文件扩展名或 MIME 类型通过校验，不代表当前浏览器一定支持其中的编码；最终仍由 `HTMLAudioElement` 解码能力决定。
- 浏览器自动播放策略可能拒绝缺少用户手势的 `play()`。当前流程主要由用户操作启动，并会展示失败信息，但仍应在真实浏览器验证。
- `useLocalAudioPlayback` 会用 source token 忽略过期的异步 `play()` 结果；但 reducer 的 `playback-ended` action 本身尚未携带 source revision。极端情况下，旧媒体源延迟到达的 `ended` 事件理论上可能推进错误 occurrence，后续可用事件令牌进一步加固。
- object URL 的创建和撤销已在代码及测试中覆盖，但测试环境使用替身，仍需在浏览器开发者工具中观察反复绑定/切歌后的资源释放情况。

### 7.3 播放器状态与产品语义

- 播放器目前同时保存 `currentIndex` 和可由序列推导的 `currentEntry`，reducer 会同步维护两者；这存在理论上的冗余状态不一致风险，当前测试未发现实际问题。
- “上一项/下一项”按展开后的 occurrence 移动。某首歌设置多次播放时，点击下一项可能仍是同一歌曲的下一次 occurrence。这是当前既定语义，不是自动跳过重复次数。
- 自动推进到未绑定歌曲时选择“停在该项并暂停”，不会跳过到后面的已绑定歌曲。这是为避免静默改变播放序列而作出的产品决定。
- 展开整个播放序列适合当前 `repeatCount <= 99` 的 MVP；未来队列规模很大时再考虑惰性索引，不需要现在提前重构。

## 9. 当前上下文中的重要决策

- 继续使用 Vite + React + TypeScript + Vitest，不为本功能引入新的依赖或状态管理库。
- occurrence 是 `queueItemId + trackId + repeatIndex` 标识的单次播放位置；队列同步不能只依赖旧数组下标。
- 当前 occurrence 存活时必须保持；消失时只向旧序列后方寻找存活项；没有后续项就结束，禁止倒退重播。
- 播放序列由临时歌单和 `repeatCount` 即时派生；不持久化派生序列或运行时 revision。
- `repeatCount` 属于独立队列项，不属于歌曲元数据；上一项/下一项按展开后的 occurrence 工作。
- 本地音频绑定关系与开发者维护的歌曲元数据分离，使用稳定歌曲 ID 建立映射。
- 当前使用原生 IndexedDB 保存 `File` 副本，没有引入 Dexie；这样满足刷新后可恢复且跨主流浏览器的 MVP 需求。
- localStorage 不保存音频本体；blob/object URL 只用于当前运行时，不能持久化，并且必须及时 revoke。
- File System Access API 暂不作为默认方案，因为支持范围和权限恢复行为不适合当前跨浏览器 MVP；未来可以做渐进增强。若项目转为桌面应用并需要稳定原文件访问，可评估 Tauri 等容器。
- reducer 继续负责纯播放器状态和 occurrence 规则；`HTMLAudioElement`、IndexedDB 与 object URL 等副作用分别放在 player、local-library 和 infra 边界内。
- 未绑定歌曲不得播放，也不应被自动静默跳过；显示“未绑定音频文件”并停在该项。
- 只接受用户主动选择的本地文件；应用不上传、不联网下载、不硬编码本地绝对路径或远程音源，也不把文件复制到仓库。
- 当前不持久化临时歌单和播放进度；不要把“本地音频映射已持久化”误写成“整个播放器状态已持久化”。
- 每次继续只做一个明确任务；明天先验证真实浏览器闭环，再根据结果决定下一项开发。

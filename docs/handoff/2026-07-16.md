## 9. 今天确定的重要技术和开发流程决策

- 用户目录变更与内置 `CatalogData` 分离，使用独立版本号，为后续持久化和迁移保留入口。
- 新增实体的稳定 ID 由调用方注入工厂生成，不使用标题、曲序、数组下标或测试随机值。
- 当前采用跨 artist/album/track 的全局 ID 唯一策略。
- 同名专辑和歌曲允许存在；名称不是实体身份。
- mutation 和 merge 保持纯函数语义，不直接修改默认目录或用户变更输入。
- 字段覆盖使用显式白名单；身份和归属字段不属于覆盖范围。
- 可选字段用 JSON 可表达的 `null` 表示清空。
- 对内置专辑新增用户歌曲时保存关系增量，以便未来默认目录更新可以继续合并。
- 合并后主动校验双向引用，不依赖浏览 helper 静默过滤损坏数据。
- MVP-01 不接 UI、存储或远程数据源；每次只完成一个明确任务。
- 本次采用“主线程唯一写入者 + 只读 Agent 分析/审查”；只读 Agent 不编辑文件、不提交代码。
- `src/types/index.ts` 虽不在 MVP-01 初始文件清单中，但仅用于沿用既有 barrel export，属于最小范围内修改。
